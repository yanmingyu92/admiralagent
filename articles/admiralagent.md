# admiralagent: Spec-to-ADaM with LLM-Translated Layers

``` r

library(admiralagent)
```

## The idea

**The LLM never writes R code.** It only *translates*: each spec
variable’s free-text derivation is mapped onto a closed vocabulary of
derivation layers (a structured JSON IR). A deterministic compiler turns
the IR into `admiral`/`metatools` code with `CHECK` validation comments
and provenance sidecars.

    P21 spec  ->  deterministic parse  ->  LLM per-variable   ->  deterministic
    (xlsx)        (metacore)              translation to IR       compile
                                             |  JSON (closed       |  script +
                                             |  vocabulary)        |  CHECK comments
                                             v                     v
                                        validate_ir()         run_validation()
                                        (schema + semantic)   (deterministic gate)
                                             \___________ __________/
                                                         v
                                           write_artifact() -> script + sidecar

Why this split: the only non-deterministic step (understanding free
text) is the LLM’s; everything with a provable right answer (code
syntax, argument schemas, validation) is deterministic. Identical IR
always yields identical code, and the LLM never sees patient data —
[`build_context()`](https://yanmingyu92.github.io/admiralagent/reference/build_context.md)
emits schema fields only.

## Walkthrough on the mock ADSL spec

Start from the bundled mock spec and classify every variable with the
zero-dependency rules backend:

``` r

spec <- mock_spec_adsl()
ir <- classify_variables(spec, dataset = "ADSL", backend = "rules")
```

Every IR — whether produced by the rules engine or an LLM — must pass
the same validation gate before any code is rendered:

``` r

problems <- validate_ir(ir)
length(problems) == 0L
#> [1] TRUE
```

The rules backend abstains (`needs_human = TRUE`) when a derivation
requires a human-only decision, e.g. AGEGR1’s categorisation
breakpoints:

``` r

vapply(ir, function(v) isTRUE(v$needs_human), logical(1))
#>  [1] FALSE FALSE FALSE FALSE FALSE FALSE FALSE  TRUE FALSE FALSE
```

Rendering is fully deterministic. Below is the head of the generated
program (truncated):

``` r

prog <- render_program(ir, backend_label = "rules")
cat(strsplit(prog, "\n")[[1]][1:16], sep = "\n")
#> # ============================================================
#> # ADSL analysis dataset program
#> # Generated by admiralagent v0.1.0 (backend: rules)
#> # DISCLAIMER: DRAFT CODE - starting point only. A qualified human
#> # must review every derivation against the spec before any use in a
#> # regulated workflow. See # CHECK comments and the artifact sidecar.
#> # ============================================================
#> library(admiral)
#> library(dplyr)
#> library(rlang)
#> 
#> # ---- Source datasets (placeholders: replace with study data) ----
#> # vs <- ...  # SDTM VS dataset
#> ADSL <- dm  # base subject-level dataset (placeholder)
```

Each step block carries its spec origin, the classifier’s rationale, a
confidence, and `# CHECK:` comments tied to the layer’s registered
checks. To *execute* the program in-process,
`execute_ir(ir, sources = list(base = dm, ex = ex, vs = vs_bds))`
evaluates each rendered block in a fresh environment and reports
`EXECUTED` / `ERROR` / `REVIEW` per variable — see
[`?execute_ir`](https://yanmingyu92.github.io/admiralagent/reference/execute_ir.md).
Artifacts are written with `write_program_artifact(ir, dir = "gen")`,
producing `<dataset>__program__<hash8>.R` plus a JSON sidecar and an
append-only, hash-chained audit log. Execution is self-auditing:
whenever logging is on,
[`execute_ir()`](https://yanmingyu92.github.io/admiralagent/reference/execute_ir.md)
writes one `execute_variable` record per variable plus exactly one
`run_manifest` record per run automatically (environment, package
versions, operator, source-data digests). Do not record a manifest by
hand for a run that went through
[`execute_ir()`](https://yanmingyu92.github.io/admiralagent/reference/execute_ir.md)
— that would duplicate the record.

## Accuracy story: rules vs the pilot1 oracle

The real question is not “does it run” but “does it match a
reviewer-approved ADaM dataset”. We executed rules-backend programs
against the CDISC pilot 1 SDTM data and compared each derived variable
with
[`pharmaverseadam::adsl`](https://pharmaverse.github.io/pharmaverseadam/reference/adsl.html)
(the published reference ADSL):

| Variable | Rule used | Result vs pilot1 |
|----|----|----|
| TRT01P | assign from DM.ARM | 100% match |
| TRTSDTM | impute DM.RFSTDTC (first, “M”) | 100% non-NA agreement, 100% NA-pattern agreement |
| TRTEDTM | impute DM.RFENDTC (last, “M”) | ~48% match — RFENDTC dominates the spec text but the pilot derives from EX |
| BMIBL | compute_param WEIGHT/HEIGHT then merge | 85.8% within 0.5 kg/m2 |

The two imperfect rows are the improvement loop working as designed:
`TRTEDTM` exposes a genuine spec-text ambiguity (RFENDTC vs last EX
dose), and `BMIBL`’s residual mismatch tracks baseline-visit scoping.
Both are flagged with `# CHECK:` comments in the generated code; neither
is silently wrong. The LLM backend targets exactly these rows — it reads
the full derivation context instead of keyword dominance.

For offline regression, the bundled corpus
(`inst/evals/spec-to-ir.jsonl`) pins expected layer chains per spec row:

``` r

res <- run_evals(backend = "rules", dataset = "ADSL")
evals_accuracy(res)  # must stay 1.0
```

The `rules` backend scoring below 1.0 on the corpus fails the package’s
own regression gate.

Be clear about what that number is: the corpus is a *regression* corpus,
not an oracle. Its `expected_args` were generated from the current
`rules` backend’s own output, so it pins today’s behaviour as the
contract — it detects drift, it does not validate correctness. Citing it
as validation evidence would be the system grading itself.

## MCP server: the same gates from any agent

The deterministic core is also exposed as a stdio MCP server (protocol
`2024-11-05`, newline-delimited JSON-RPC 2.0) with five tools:

| Tool | Purpose |
|----|----|
| `aa_classify` | spec rows -\> layer IR (rules backend) + validation problems; `ir` is `null` whenever `problems` is non-empty |
| `aa_validate_ir` | parse/normalize any IR array, run [`validate_ir()`](https://yanmingyu92.github.io/admiralagent/reference/validate_ir.md) |
| `aa_render_program` | IR -\> admiral program with CHECK comments + hash; no `warnings` field (a compat conflict aborts instead) |
| `aa_dependency_report` | undefined step inputs (`variable, input, dataset, issue`) |
| `aa_evals` | run the bundled corpus, report rules accuracy |

On this surface both free-text IR fields are digested at ingress:
`spec_origin` comes back as `origin:<hex>` and `rationale` as
`rationale:<hex>`, so client-supplied text is never echoed into
responses, generated code or sidecars (in-process callers keep verbatim
`spec_origin` provenance).

No network, no LLM, no API keys — every tool is base R + jsonlite +
digest. Register it (e.g. for Claude Code) via:

``` json
{
  "mcpServers": {
    "admiralagent": {
      "command": "Rscript",
      "args": ["/path/to/admiralagent/tools/mcp_server.R"]
    }
  }
}
```

The tool layer is in-process testable via
[`mcp_tool_specs()`](https://yanmingyu92.github.io/admiralagent/reference/mcp_tool_specs.md)
and
[`mcp_handle_request()`](https://yanmingyu92.github.io/admiralagent/reference/mcp_handle_request.md);
the blocking loop itself is
[`mcp_serve()`](https://yanmingyu92.github.io/admiralagent/reference/mcp_serve.md).

## Improvement-loop philosophy

Every iteration follows probe -\> finding -\> fix -\> regression:

1.  **Probe**: execute generated programs against real SDTM (pilot1);
    every ERROR/FAIL/MANUAL becomes a numbered finding.
2.  **Fix in three layers at once**: semantic validation
    ([`validate_ir()`](https://yanmingyu92.github.io/admiralagent/reference/validate_ir.md),
    [`ir_dependency_report()`](https://yanmingyu92.github.io/admiralagent/reference/ir_dependency_report.md)),
    prompt rules
    ([`build_system_prompt()`](https://yanmingyu92.github.io/admiralagent/reference/build_system_prompt.md)),
    and a regression test.
3.  **Never repeat history**: past LLM failure modes (step-level `on`,
    JSON array simplification, cross-dataset `assign`, admiral argument
    renames) are all locked behind tests and normalizations.

When the classifier is unsure it abstains — `needs_human` variables get
a review header instead of guessed code. The package’s promise is not
“no humans”; it is “no silent errors”.
