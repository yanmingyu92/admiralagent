## 知乎（深度技术长文，~2500 字）

**标题候选**：《我让 LLM 一行 R 代码都不许写，然后把真实药审数据丢了进去》

1. **开场钩子**：临床编程是强监管行业，"LLM 帮你写 SAS/R 代码"的 demo 在
   GxP 语境下是死路——失败模式不是跑不通，而是"跑得通但悄悄错"。
2. **架构主张**：LLM 只做翻译（spec 自由文本 → 封闭词汇表 Layer IR），
   R 代码由确定性编译器生成。可校验、可哈希、可签署的是 IR，不是散文也不是代码。
3. **实验设计**：CDISC pilot5 真实递交 spec（49 个 ADSL 变量）+ 原始 SDTM +
   递交版 ADSL 作为 oracle；rules（零成本基线）与 DeepSeek 双后端对照。
4. **真实数字**：rules 弃权 32/49 但做对的 15/15 全中；DeepSeek 多做 4 个变量，
   oracle 全对 16/19；双后端层链一致率 82%；3 采样共识 12/12 全票；
   成本 84 秒 + 0.009 美元。
5. **边界即卖点**：27 个弃权逐一有理由——词汇表里没有条件层，所有
   `Y if ...` 旗标集体弃权；引用 SAP 的、查不到 codelist 的，一律说"我不知道"。
   会幻觉这些的系统不如会弃权的系统。
6. **错误分类学**（诚实是记忆点）：HEIGHTBL/WEIGHTBL 原始一致率 19.7%/8.7%，
   但按 oracle 自身存储精度算是 98.8%/94.5%——oracle 做了 spec 没写的四舍五入；
   AGEGR1N 全部 11 例分歧都是恰好 80 岁的受试者（spec 文本自相矛盾）；
   另登记 1 个真实包缺陷（F-01：validate_ir 不追踪 merge 后的列改名）。
7. **收尾**：约束不是限制 LLM，是让审计变便宜。失败模式从"悄悄错"变成"大声弃权"，
   这是监管编程唯一负担得起的失败模式。附 repo / pkgdown / REPORT 链接。

## 小红书（短图文，5-6 张卡片）

**标题候选**：《不让 AI 写代码，反而更敢用｜药厂编程的反向操作》

- **卡 1（钩子）**：别人的 demo：AI 一把梭写完整套分析代码。
  我的规则：AI 一行 R 代码都不许碰。结果反而能量化了。👇
- **卡 2（怎么做到的）**：AI 只负责"翻译"——把 spec 里的人话翻成受控词汇表的
  中间表示（IR），真正的 R 代码由确定性模板生成。同一份 IR，永远生成同一份代码。
- **卡 3（真实战绩）**：拿 CDISC 官方 pilot5 药审数据实测：49 个变量，
  AI 自动搞定 20 个，其中 16 个和官方递交结果 100% 一致；
  全程 84 秒，成本不到 1 分钱人民币。
- **卡 4（最反直觉的发现）**：剩下 27 个变量 AI 全部举手说"我不会"——
  而且每个都给了理由。在药审场景里，"会弃权"比"敢硬答"值钱一百倍。
- **卡 5（连错误都很诚实）**：两个"对不上"的变量，最后发现是官方数据悄悄做了
  spec 里没写的四舍五入——按它自己的精度算其实 98.8% 一致。
  还有一个分歧全是 80 岁受试者：spec 原文自己就互相矛盾。
- **卡 6（CTA）**：开源 MIT，GitHub 搜 admiralagent，一条命令复现全部数字。
  评论区聊聊：你敢让 AI 在你的工作里"只说不知道"吗？

**差异化记忆点**（两平台共用）：「LLM never writes R code」+
「27/49 次弃权，次次有理由」+「不一致率背后是 oracle 没写进 spec 的舍入约定」。
